# NAVA — Neural Agentic Virtual Agent

> **Un agent IA local et agentique capable de transformer une intention humaine en actions réelles, livrables vérifiés et résultats prouvés sur un PC Windows.**

**Développé par IA NAVA — France**

[Site officiel](https://www.ianava.fr) • [Contact](mailto:contact@ianava.fr)

---

## NAVA n'est pas un chatbot

Un chatbot répond.

**NAVA agit.**

```text
Utilisateur
    ↓
Intention
    ↓
Compréhension
    ↓
Décision
    ↓
Plan d'action
    ↓
Exécution sur le PC
    ↓
Vérification
    ↓
Preuve
    ↓
Mémoire
```

NAVA est conçu comme un **agent IA opérateur** capable de comprendre une demande formulée naturellement, de sélectionner les capacités nécessaires et d'agir dans l'environnement informatique réel de l'utilisateur.

Son objectif n'est pas seulement de produire une réponse.

Son objectif est de produire un **résultat réel, vérifié et exploitable**.

---

# La vision NAVA

NAVA repose sur une architecture simple à comprendre :

```text
NAVA        = le cerveau
Windows     = l'environnement d'action
Logiciels   = les outils
Fichiers    = les livrables
Mémoire     = l'expérience
Vérification = le contrôle
Preuves     = la validation
```

L'utilisateur formule un objectif.

NAVA doit ensuite être capable de déterminer :

- ce qui est réellement demandé ;
- les informations nécessaires ;
- les capacités à mobiliser ;
- les logiciels à utiliser ;
- les actions à exécuter ;
- les résultats à vérifier ;
- les actions nécessitant une validation humaine.

---

# Une commande naturelle, plusieurs actions

NAVA est conçu pour recevoir des demandes comme :

```text
Analyse mes rendez-vous de la semaine,
prépare les documents nécessaires
et crée les brouillons de mails correspondants.
```

ou :

```text
Recherche les tendances IA 2026 pour les PME
et crée un rapport exploitable par un dirigeant.
```

ou encore :

```text
Analyse ce dossier client,
prépare le devis,
le planning,
le rapport
et le mail de transmission.
```

L'utilisateur décrit le **résultat attendu**.

NAVA détermine comment l'obtenir.

# Local First

NAVA est développé avec une approche **Local First**.

L'objectif est de permettre l'utilisation maximale des capacités directement sur le poste utilisateur.

```text
NAVA
├── IA locale
├── Windows
├── applications locales
├── fichiers locaux
├── mémoire
└── vérification
```

Des modèles ou services cloud peuvent être utilisés lorsque cela apporte une valeur réelle et lorsque les règles de confidentialité de la mission le permettent.

L'utilisation du cloud reste contrôlée.

---

# Intelligence hybride

NAVA peut exploiter différents moteurs selon le type de mission.

L'architecture vise à choisir le moteur approprié en fonction :

- du besoin ;
- du type de livrable ;
- de la confidentialité ;
- des capacités disponibles ;
- du contexte ;
- de la qualité attendue.

L'objectif n'est pas d'utiliser systématiquement le modèle le plus puissant.

L'objectif est d'utiliser **la bonne intelligence au bon moment**.

---

# Décision agentique

Avant et pendant une mission, NAVA évalue notamment :

- les capacités disponibles ;
- les résultats précédemment obtenus ;
- les preuves existantes ;
- les alternatives disponibles ;
- les risques ;
- les possibilités de reprise ;
- les informations manquantes.

Une capacité ne doit pas être considérée comme fiable simplement parce qu'elle existe dans le code.

Elle doit avoir été **réellement exécutée et vérifiée**.

---

# Vérification avant déclaration de réussite

Principe central de NAVA :

> **Une action exécutée n'est pas nécessairement une mission réussie.**

NAVA cherche à vérifier :

```text
Demande utilisateur
        ↓
Effets attendus
        ↓
Actions réalisées
        ↓
Résultats obtenus
        ↓
Vérification
        ↓
Preuve
```

Une mission n'est validée que lorsque le résultat attendu peut être démontré.

---

# Preuves d'exécution

Selon la mission, NAVA peut utiliser différents éléments de preuve :

- existence du fichier ;
- contenu du fichier ;
- propriétés du document ;
- état d'une application ;
- capture ;
- journal d'exécution ;
- contrôle après sauvegarde ;
- réouverture du livrable ;
- état système ;
- vérification fonctionnelle.

L'objectif est de rapprocher l'agent IA d'un principe simple :

> **Ne pas seulement dire que le travail est terminé. Le démontrer.**

# Apprentissage contrôlé

Lorsqu'une capacité manque, le principe recherché est :

```text
LACUNE
  ↓
ANALYSE
  ↓
HYPOTHÈSE
  ↓
TEST MINIMAL
  ↓

  ↓
VALIDATION
  ↓
```

Une nouvelle capacité ne doit pas être promue uniquement parce qu'une solution semble fonctionner.

Elle doit être testée et vérifiée avant d'être considérée comme réutilisable.

# Sécurité et contrôle humain

L'autonomie de NAVA ne signifie pas absence de contrôle.

Les actions sensibles peuvent nécessiter une validation avant exécution, notamment :

- envoi d'un mail ;
- publication ;
- contact externe ;
- invitation ;
- suppression ;
- modification irréversible ;
- opération présentant un risque métier.

Le principe est :

```text
Autonome sur les actions sûres
+
Validation humaine sur les actions sensibles
```

# Philosophie de développement

NAVA suit plusieurs principes :

### 1. L'effet réel avant la démonstration

Une fonction n'existe réellement que lorsqu'elle produit son effet sur le PC.

### 2. La preuve avant la déclaration

Une mission réussie doit pouvoir être vérifiée.

### 3. L'intention avant le workflow

L'utilisateur exprime un objectif, pas une procédure informatique.

### 4. La réutilisation avant la complexité

Les capacités existantes sont privilégiées avant la création de nouveaux mécanismes.

### 5. L'apprentissage avant le contournement

Lorsqu'un problème apparaît, NAVA doit progressivement apprendre à l'analyser et à le résoudre.
